# Drift — Phase 3: equipment-derived ship capabilities

`ship_capabilities.gd` builds the profile used by ship flight and fleet logic from existing module statistics, admin overrides and normalized equipment slots. It exposes absolute cruise/boost/hyperjump speeds, acceleration and turn rate, hull/shields, cargo capacity and live free space, mining rate and a weapon-strength proxy. `can_perform` and `suitability` distinguish an equipment check from comparative scoring. The existing six designs are unchanged and carry no hardcoded roles.

Mining and weapons are counted from the same normalized slots the player controller uses. Legacy turret art is not counted a second time, and the existing physical cargo module and administrative cargo setting determine capacity. Mining and tritium collection check the same free-space calculation. Profiles are derived and rebuilt on load, design changes and successful admin edits; no save schema change was needed. The mining rating describes installed tools, not turret aim or extraction at a specific range. Task scores are heuristics rather than a simulated damage-per-second or route-profitability model.

Changed `scripts/game.gd`, added `scripts/ships/ship_capabilities.gd` and `tests/ship_capabilities_test.gd`, and extended the flight persistence test to verify that reloaded slots and cargo overrides rebuild the correct profile. Eleven headless tests passed. Existing four-speed flight/mining parity passed. M4, 1,000 systems, one active ship: 0.741 ms per gameplay tick and 0.536 ms synchronous presentation in the headless baseline.
